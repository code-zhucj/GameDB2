# 编码规则

在动手写任何代码之前，必须遵守以下三条规则：

## 1. 最小改动原则

- 以最精简的方式实现需求，代码尽可能简单高效
- 用最少的代码改动达成目标
- 不做过度设计，不引入不必要的抽象

## 2. 不做顺手优化

- 只修改需求边界内的逻辑
- 需求范围外的代码，即使发现可优化之处，也不能擅自改动
- 如果确实发现有值得改的地方，必须先向用户说明并取得明确同意后才可执行

## 3. 每次修改都要有测试

- 每次代码修改完成后，必须编写对应的测试用例
- 测试用例必须能正常运行并通过
- 确保改动行为符合预期
